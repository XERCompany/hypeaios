# Storage / USB / VFS (P16) + hardening (P17)

All landed 2026-11-28 on `devin/hypeai-font-ui`. P16 = issues #100-#103, #105; P17 = #104, #106, revsvc, and the DHCP options fix.

## P16 — device + VFS breadth

- **PCIe ECAM + MSI/MSI-X** (#102, `e97a05d`): `acpi/mcfg.cc` parses MCFG segment groups (`mcfg segs=N`); `pci_ecam_addr` picks ECAM vs CF8/CFC per bus, config offsets widened to u16 so the full 4 KiB extended space is reachable (`pci ecam=ok base=`); `pci_capability` walks ext caps at 0x100 (`pcie caps=N`); `pci_msi_setup()` + new `pci_msix.cc` program message addr `0xFEE00000|(lapic<<12)`/data=vector into the LAPIC (`msi setup=ok vec=`, `msix setup=ok vec=`); `pci_irq.cc` legacy-line fallback.
- **AHCI 1.3 + block dispatch** (#100, `dddbd28`, merge `9b984a1`): `kernel/block/ahci.cc` — PCI class 01/06/01 probe, ABAR (BAR5), BIOS/OS handoff via CAP2.BOH, per-port PMM command list + FIS receive + command tables, FIS H2D IDENTIFY / READ DMA EXT / WRITE DMA EXT / FLUSH (LBA48) through PRDT DMA; bounded polls, COMRESET on timeout. New `kernel/block/blockdev.{h,cc}` dispatch layer; hypeblob rides it → HYPEDATA works with no IDE. Markers `ahci dev=ok ports=N`, `ahci portN model=`, `ahci rw=ok`.
- **xHCI + HID boot protocol** (#101, `13f98fc`, merge `e9b48d4`): `kernel/usb/xhci.cc` — halt/reset, DCBAA, command ring + polled event ring, Enable Slot / Address Device / Evaluate Context / Configure Endpoint; EP0 GET_DESCRIPTOR + SET_CONFIGURATION + SET_PROTOCOL boot; kbd 8-byte reports → set-1 scancodes → `emit_key_event`, mouse reports → `MsauxPacket` queue drained by `cursor_poll` (same path as PS/2). Scope: ≤8 slots, root ports only, no hubs/MSI/mass-storage; runtime stage `usb.xhci` (pri 57). Markers `xhci dev=ok slots=N`, `usb kbd=ok`, `usb mouse=ok`, graceful `xhci dev=absent`.
- **VFS fd table + reclaim + write-through** (#103, `fd0a1fb`, merge `65f2302`): `kernel/vfs/fdtable.cc` 64 fds (0/1/2 = serial console), generation-tagged so stale fds fail decode; `fs_open/close/pread/pwrite/fread/fwrite/seek/flush` while path-based `fs_read/write` stay unchanged. memfs bump arena → per-disk 4 KiB block bitmap: delete/shrink reclaim, honest `NoSpace`. Dirty mask + debounced `fs_autosync()` (250 ms) → `hypeblob_sync()` write-through; `fs_sync()` forces. Markers `vfs fd=`, `vfs reclaim=`, `vfs dir items=`, `vfs sync=`.
- **NVMe 1.4** (#105, `5787139`): `kernel/block/nvme.cc` — PCI class 01/08/02, admin SQ+CQ on PMM with CAP.DSTRD doorbells, serialized admin cmds polled via CQ phase bit; NVM READ/WRITE/FLUSH on I/O qp1 (64 entries) via PRP1/PRP2/PRP-list; 512B wrappers chunk ≤64 KiB, honor MDTS + namespace LBA size (bounce-buffered sub-block reads). blockdev order: NVMe > AHCI > ATA PIO. Markers `nvme dev=ok ns=N lba=`, `nvme ns1 cap=`, `nvme rw=ok`.

## P17 — services, SMP, fixes

- **RevServices + RevDBGService** (`ed59fad`, merge `899fa7b`): `kernel/svc/revsvc.cc` — per-service 8-pair kv store (`svc_data_set/get`); `klog::set_sink` + `svc_attach_klog()` tee `svc:<name>` klog lines into the service's log ring; op markers `revsvc registered=N`, `revsvc <name> start|stop|restart=ok|fail`; `HxerHeader.on_click` + `wm_invalidate_app()` make RevDBGService's list and Start/Stop/Restart buttons interactive (30-tick damage-aware refresh).
- **SMP AP bring-up** (#104, `5b05ce1`, merge `1014d54`): `arch/x86/ap_tramp.asm` real-mode→long-mode blob copied to 0x6000 (SIPI vector 0x06); `smp.cc` INIT assert + 10 ms + SIPI x2 via LAPIC ICR, 1 s bounded start wait, per-AP PMM stack + LAPIC/LVT-timer enable; MADT captures per-CPU uid/lapic_id; `idt_load` shared IDT reload for APs; global tick increments on BSP only so AP timers can't multiply the time base; runtime stage `smp.ap` (pri 56). Markers `smp cpus=N`, `smp ap<N> lapic=X online`, `smp ap<N> ticks>0 ok`; `smp cpus=1` on 1-CPU machines.
- **DHCP variable-length options fix** (`347bc22`, merge `5e2f5a1`): QEMU slirp offers/acks arrive shorter than `sizeof(DhcpPacket)` — the options tail isn't padded to 312 B — so `handle_dhcp()`'s full-struct length check dropped every reply (`dhcp ip=none` despite a working TX/RX path). Now requires only the fixed BOOTP header + magic cookie; `dhcp_option()` already bounded by actual length. Also added `net tx=N rx=N` frame counters.
- **FAT32 read/write** (#106, `7b8d096`, merge `d1bd82d`): `kernel/vfs/fat32.cc` — MBR partition scan (types 0x0B/0x0C) with GPT fallback on protective MBRs (EFI System / Basic Data GUIDs), BPB validation, cluster-chain walks with single-sector FAT cache, 8.3 + LFN (UCS-2) dir enumeration; bounded write path (8.3 create/rewrite, free-scan alloc mirrored to all FAT copies, dir-chain growth, delete marks entry+LFN 0xE5 and frees the chain, mkdir with `.`/`..`). Routes as `HYPEOS://F`; stock image has no partition table → `fat32 part=none`. Markers `fat32 part=ok label=`, `fat32 mount=F ok`, `fat32 rw=ok` after the hypeai.txt write-read-compare selftest.
