# Payload packs (ticket #74, spec #71)

As of 2026-11-28 the HYPEDATA blob (LBA 8258, built by `tools/mkimage.py`)
carries four content packs so the >1GB image is justified by features, not
padding. Boot markers: `blob files=`, `payload packs=4`, `fs ufiles=`,
`dxbg walls=`, `hxer sync=`.

## Mount routing

`hypeblob_mount()` mounts each blob entry into memfs. Entry names starting
with `u/`, `s/` or `t/` route to `HYPEOS://U/`, `S/` or `T/` respectively;
all other names land under `HYPEOS://S/data/<name>`.

## Packs

- **wallpaper pack** — `payload/wallpapers/*.png` (PIL, 160x90, generated by
  `tools/gen_payload.py`) -> `U:/wallpapers`. dxbg seeds 3 more procedural
  walls into the same dir; `dxbg walls=8` (cap `dxbg_max_wallpapers=8`).
  Keep wallpapers at 160x90: PNG decode uses ~4 frame-sized buffers inside
  dxbg's 384KB io arena; 320x180 overflows it and `dxbg apply` fails.
- **docs pack** — existing `docs/wiki`+`docs/research` md plus generated
  `payload/help/*.txt` (about, keyboard, paths, services) -> `S:/data/help`.
- **font pack** — `payload/fonts/Montserrat-Bold.ttf` (OFL, JulietaUla
  upstream) + `README.txt` -> `S:/data/fonts`. Payload only; no parser
  changes.
- **app pack** — `tools/mkimage.py` serializes the five builtin HxerHeaders
  in hxpack format (64B header + 8B entry tag). Entry addresses come from
  `build/kernel.map` (`-Wl,-Map` on the kernel link), so blob `.hxer` files
  decode identically to `hypefile_install` output. They mount to `U:/apps`;
  `hypefile_sync` now scans both `S:/apps` and `U:/apps` (`hxer sync=9`).
  `hypefile_install` at boot installs all 5 builtins (`vfs hxer=5`): system
  kinds -> `S:/apps/*.hxersys` (FS_SYS-locked), user kind -> `U:/apps`.

## Regeneration

`python tools/gen_payload.py` rewrites wallpapers + help pages
deterministically; outputs are committed. `.hxer` files are *not* committed —
they are regenerated per build because entry addresses move with the link.
